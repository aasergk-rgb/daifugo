# 大富豪 ― DAIFUGO

実在するルールのほぼすべてを自由に組み合わせて遊べる、ブラウザで動く大富豪（大貧民）です。

- **CPU対戦**（3〜6人／CPUの強さ4段階）
- **オンライン対戦**（WebSocketサーバー または P2P。サーバーがなくても遊べます）
- **ルールを自由に設定**：基本ルール／日本大富豪連盟 公式ルール／定番ローカル／全部盛り のプリセットに加え、40以上の項目を個別に変更・カスタムルールとして保存
- **和モダンの凝ったデザイン**：SVGで描いたオリジナルのトランプ、革命・八切りなどの全画面演出、琴と太鼓の合成サウンド、4種のテーマ（漆黒金箔・翠緑カジノ・夜桜・ネオン東京）と4種のカード裏面（麻の葉・青海波・亀甲・七宝）

## 遊び方（ローカルで起動）

```bash
npm install
npm run dev          # ブラウザ版（http://localhost:5173）。CPU対戦・P2P対戦はこれだけで遊べます
npm run dev:server   # （別ターミナル）オンライン対戦サーバー。dev からは /ws に自動でつながります
```

本番ビルドとサーバー起動：

```bash
npm run build        # dist/（ブラウザ）と dist-server/（サーバー）を生成
npm start            # http://localhost:8787 で配信 + オンライン対戦
```

Docker：`docker build -t daifugo . && docker run -p 8787:8787 daifugo`

## オンライン対戦の仕組み

| 方式 | 使いどころ | 説明 |
| --- | --- | --- |
| サーバー | `npm start` や Docker で公開したとき | サーバーがゲームを進行（不正できない）。切断しても同じ席に再接続でき、その間はCPUが代打ちします |
| P2P | GitHub Pages などの静的ホスティング | ルームを作った人のブラウザがホストになり、WebRTC（PeerJS）で直接つながります。ホストはページを閉じないでください |

「接続方式：自動」では、対戦サーバーが見つかればサーバー、なければP2Pを使います。
ルームを作ったら、表示されるコードか招待リンクを友だちに送ってください。空いた席はCPUが埋めます。観戦・チャット・スタンプ・持ち時間にも対応しています。

P2Pのシグナリングには既定でPeerJSの公開サーバーを使います。自前の [PeerServer](https://github.com/peers/peerjs-server) を使う場合は、ビルド時に `VITE_PEER_HOST` / `VITE_PEER_PORT` / `VITE_PEER_PATH` / `VITE_PEER_SECURE` を指定するか、URLに `?peerHost=…&peerPort=…` を付けてください。

GitHub Pages で公開するには、Settings → Pages → Source を「GitHub Actions」にして `main` に push します（`.github/workflows/pages.yml`）。

## 対応ルール

**基本**：階段（最小枚数・強さ比較方式）、複数枚出し、ジョーカー（0〜2枚・ワイルド）、カード交換（枚数変更可）、パスの扱い（再参加可／流れるまで不可）、最初の親（♦3・♠3・ランダム／ダイヤ3スタート）、2戦目以降の親

**革命系**：革命（必要枚数変更可・革命返し）、階段革命

**縛り**：マーク縛り（ジョーカー補完あり）、数字縛り、激縛り

**効果札**（発動させる数字も変更可）：8切り、5飛び、7渡し、9リバース、10捨て、11バック、Qボンバー、階段に含まれる効果札の発動

**特殊な出し**：スペ3返し、砂嵐、救急車、ろくろ首、シックスカード、最強階段（ジョーカーを頂点に）、ダブルジョーカー

**上がり・身分**：反則上がり（ジョーカー・2〔革命中は3〕・8切り・♠3単体を個別に設定）、都落ち、下剋上、天変地異

**試合形式**：ゲーム数、セット（身分リセット）、ブラインドカード、得点方式（シンプル／連盟式 6・4・2・0）、セット最終戦ボーナス、持ち時間

「連盟公式ルール」プリセットは日本大富豪連盟の公式ルールブックに準拠しています（ジョーカー2枚・ブラインド2枚・4ゲーム×3セット、パスしたら場が流れるまで出せない、階段は最弱札で比較、反則上がりは出す前の状態で判定、反則上がり者は都落ち者より下、など）。

## CPUの強さ

| 強さ | 思考 |
| --- | --- |
| よわい | 手札評価にランダム性を加え、ときどきミスをする |
| ふつう | 手札をペア・階段に組み分けて、弱い組から効率よく出す |
| つよい | ＋カウンティング（見えていないカードから「誰にも返されない手」を判定し、勝ち筋を読む） |
| 鬼 | ＋モンテカルロ・シミュレーション（相手の手札を推定して何百局も先読み） |

ブラウザではCPUの思考をWeb Workerで行うため、鬼が考えている間も画面は止まりません。

## 構成

```
src/engine/   ルールエンジン（純粋関数）・CPU・各プレイヤー向けの情報投影
src/net/      ルーム（進行の権威）、プロトコル、接続（ローカル / WebSocket / P2P）
src/ui/       React UI、演出、サウンド
server/       Node.js サーバー（静的配信 + WebSocket）
tests/        ルール・CPU・ルームのテスト
```

同じ `Room` クラスが、オフライン対戦・P2Pホスト・サーバーのすべてで使われます。他のプレイヤーの手札がクライアントに送られることはありません。

```bash
npm test        # ルールの単体テスト、全プリセット×3〜6人の自動対戦、ルームの結合テスト
```
